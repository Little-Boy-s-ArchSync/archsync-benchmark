# A–B–C–D measurement-study infrastructure

Status: **technical dry-run only — no participant, agent, pilot, or final-study result**.

The task suite keeps the baseline, feature sequence, expected behavior and acceptance commands outside the treatment configuration. A is Human, B is AI, C is AI+repository context and D is AI+repository context+ArchSync evidence. The committed tasks exercise the instrumentation on the existing Order Platform lab; they are not a frozen final sample and cannot establish productivity or drift claims.

The library validates immutable task IDs, A–D treatment isolation, proposed/frozen manifests, complete event envelopes, failure-retaining metric denominators, five-condition multi-source ablation design and deterministic normalized analysis artifacts. `pnpm study:verify` performs a synthetic A–D logging dry run with no model or participant.

Every event payload must contain the artifact it claims to record. Run start binds environment, task-suite and study-manifest hashes; baseline binds commit/tree; AI conditions bind redacted prompt/response/provider-configuration artifacts; submission binds a non-empty commit chain and acceptance commands; test records bind commands to results and counts; finish records status, time, usage, counts, deviations and end time. Empty placeholder payloads fail. The recorded test commands must match the submitted acceptance commands exactly, including order and multiplicity. Finish counts must match the recorded findings, approvals and repairs; failed acceptance tests cannot become a completed run. Human-only condition A cannot report model tokens, and the declared end time must fall between test recording and finish recording. Failed and inconclusive envelopes remain valid and visible when they preserve this evidence. These checks establish internal consistency only; they do not authenticate external artifacts or provide human approval.

`await validateInstrumentationArtifacts(events, readArtifact)` adds strict byte verification after those structural checks. Every event must have a nonempty `attempt_id`, stable within its run and never shared with another run, plus `artifact: { path, sha256 }`. Each receipt contains exactly `{ schema_version: 1, event: <the complete event without artifact> }`. The verifier hashes the original receipt bytes, parses the JSON and compares every event field, including run, attempt, task, condition, event ID, timestamp and payload. A correctly hashed receipt from another attempt, or a changed test result with its earlier receipt, fails. Each attempt still needs its own unique `run_id`; retries cannot overwrite or be combined with a previous run's envelope.

The strict payload also supplies `environment_path`, `task_suite_path` and `study_manifest_path` at run start; `tree_path` at baseline; and `provider_config_path` plus `redaction.audit_path` for model prompts. Existing `prompt_path` and `output_path` identify prompt and response bytes. Each path is checked against its corresponding existing SHA-256 field, including `response_sha256` for `output_path`. Missing, unreadable, empty or altered bytes fail. Paths use relative ASCII letters, digits, underscores, dots, slashes and hyphens, without empty, `.` or `..` segments. The injected reader must return `Uint8Array`/`Buffer` bytes from a trusted store that confines reads to its artifact root, including symlink resolution; it must not decode paths as URLs. No default filesystem or network reader is installed. The verifier snapshots event claims before awaiting the reader and never edits or drops failed/inconclusive records.

This proves correspondence to the supplied event log and exact byte hashes. It does not authenticate who produced that log, execute acceptance commands, independently inspect a Git tree, verify redaction decisions or signatures, or establish that a manifest has genuine human approval. A caller must preserve the independently reviewed immutable event-log pins and supply a trusted capture/reader before real collection. The synthetic dry run exercises the strict interface with clearly marked in-memory fixture bytes; its suite, manifest and tree references are synthetic stand-ins, not an approved capture or study freeze.

STUDY-104 descriptive metric preparation is pinned to Paper PR #17 and the proposed STAT-101 file/hash in `statistical-plan-source.json`. Outputs retain assigned and analyzed `n`, status counts, explicit numerator/denominator/value triples, Wilson intervals for binary proportions, and observed median/IQR duration summaries. This linkage is preparatory: STAT-101 is not preregistered or frozen, so the helper makes no population or experimental claim.

Main execution remains blocked by EXP-103, STAT-101, PILOT-101, ETH-101 and DATA-101. A frozen manifest requires separate human ethics, data and Lead approvals. Pilot data must remain outside the final sample, and failed/inconclusive runs must remain in the dataset.
